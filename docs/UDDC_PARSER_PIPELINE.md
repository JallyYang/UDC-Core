# UDDC 解析流水与逐拍行为

当前核心将 `uddc_channel_split` 分成四段组合逻辑，中间有三个独立可选的弹性
寄存点，固定解析结果级保留；所有开启的边界和结果级均使用两项 `de_rs_reg` 缓冲。默认三个寄存点全部开启。
变量定义、逐函数解析和字段例子见 [channel_split 模块详解](UDDC_CHANNEL_SPLIT.md)。

## 变量和开关

| 名称 | 含义 |
| --- | --- |
| `s_region` | 当前快照，最多 96B，包含两个包及填充 |
| `s_available_bytes` | 当前已收到的有效字节数，不是单包尺寸 |
| `s_final` | 整个压缩区域已收齐，该包不会再有更长快照 |
| `s_response_valid` | 当前快照本拍处理结束，包括数据不足而不产生结果的快照 |
| `s_done` | 当前快照已解析成功，或 final 已到、可以交付最终错误；只在响应有效时解释 |
| `s_streaming` | 静态配置，选择连续前缀调度或响应驱动调度 |
| `split.snapshot_queue_ready` | 本地快照队列是否还有空间，与解析器ready无组合关系 |
| `split.snapshot_enqueued` | 新快照已被本地队列接收，并非解析器已消费 |
| `split.offered_bytes` | 当前单元最近一次已入队快照的有效字节数，用于判断pkg0是否有新前缀 |
| `result_sent[{unit_id,pkg_id}]` | 该包是否已提前交付过结果，用于抑制重复成功 |

| 宏 | 默认 | 寄存前的组合工作 | 对应模块参数 |
| --- | --- | --- | --- |
| `UDDC_PARSE_INDEX_REG` | 1 | 包头/格式/策略解析、索引提取、差分位宽解码 | `INDEX_REGISTERED` |
| `UDDC_PARSE_OFFSET_REG` | 1 | 偏移前缀求和的前三层：距离1、2、4 | `OFFSET_REGISTERED` |
| `UDDC_PARSE_LAYOUT_REG` | 1 | 偏移后三级：距离8、16、32；锚点/差分位置、尺寸与范围检查 | `LAYOUT_REGISTERED` |

宏为 1 时打一拍，为 0 时数据、valid、ready 组合直通。默认定义位于
`rtl/uddc_channel_split.sv`，可用编译选项覆盖，例如：

```text
+define+UDDC_PARSE_OFFSET_REG=1
+define+UDDC_PARSE_INDEX_REG=1
+define+UDDC_PARSE_LAYOUT_REG=0
```

此配置增加两拍；全部开启增加三拍，全部关闭不增加内部寄存级。
可选寄存点仍为三个，边界改为 INDEX/OFFSET/LAYOUT。
每个寄存级携带对应快照及 unit_id/pkg_id/final，采用
`ready = 本级占用数 < 2`，与下游ready无组合关系。占用一项可同拍读写；
占用两项时本拍即使出队也不入队，下一拍恢复接收。每级最小延迟仍为一拍。
复位清除计数、指针、有效位和去重状态，NORST=1不清零数据；组合逻辑不直接受复位控制。
详见 [de_rs_reg](DE_RS_REG.md)。

位置计算的六层前缀求和拆为3+3：前三层在 OFFSET 寄存点前，后三层在其后，
再执行字段定位和范围检查。默认跨两个时钟级；关闭 OFFSET 后可合并为组合通路。
这里求和的是编码位宽，后级 `uddc_delta_cal` 的四级累加恢复的是样本数值，两者不同。
包头字段较短，现与索引解析共用第一级；原包头后单独的寄存点已移到前缀求和中间。
原宏 `UDDC_PARSE_HEADER_REG` 已更名为 `UDDC_PARSE_OFFSET_REG`，模块参数
`HEADER_REGISTERED` 同步改为 `OFFSET_REGISTERED`；旧编译选项和参数覆盖需相应修改。
最后一段按绝对 bit 位置直接提取锚点、差分，再符号扩展和排列通道平面。
这避免先动态提取整个通道字段、再动态提取单个差分的两次选择。

## 首拍启动与连续前缀

首拍 32B 到达后立即形成首份请求。随后 64B、96B 快照可以连续进入流水，
不等待前一份响应。每份快照独立解析；不保存上一份快照的半包字段，后续更长
快照重新解析。前面的索引/位置计算与后面的输入接收、包头解析重叠执行。

核心中 `MERGE_PREFIXES=1`，只要任意解析寄存点开启，`s_streaming=1`。
该配置经 `uddc_dic_dec`、`uddc_dec_core` 接到 `uddc_dec_split.pkg_streaming`。

- 流水模式：有效字节增加就可更新 pkg0 请求；pkg0 **最终快照进入本地两项队列**后切到
  pkg1；pkg1 最终快照入队后继续调度下一 unit，不等待解析响应。
- 全部寄存点关闭：`s_streaming=0`，按有效响应中的 done 决定重试或提前切包。
- 队首在解析器反压期间保持不变，第二项仍可缓存下一份快照；队列满后停止入队。
  恢复后未入队的过时前缀可以跳过，已入队快照保持原顺序。
- pkg0 从区域低端读取，pkg1 从整个占用区域高端读取，所以 pkg1 等区域收齐后调度。

多个快照可能都成功解析同一个包。第一份成功结果写入解析结果缓冲后置位 `result_sent`，
后续重复快照继续消费但不再输出。最终快照消费后清除对应位，供 slot 重用。
因此流水模式中，即使早期成功，也必须发送最终快照。若之前没有成功结果，
最终快照失败时交付一次 error=1、载荷清零的结果。

独立实例可用 `MERGE_PREFIXES=0` 保留每份快照各自输出的接口语义。
`s_done` 不代表差分恢复、输出完成或 slot 已释放。需要输出新结果时，响应会等待
结果缓冲可接收；失败的非最终前缀和重复前缀可以直接消费。

## 默认配置逐拍示例

T0 为第一拍输入握手，输入连续、下游始终接收、无前序排队。以 96B unit、
`32B < pkg0 <= 64B` 为例，表中运算结果在对应时钟沿寄存：

| 时钟沿 | 输入/请求 | pkg0 的快照解析 | pkg1 / 后级 |
| --- | --- | --- | --- |
| T0 | 接收 32B，提交 context，寄存首份快照 | — | — |
| T1 | 接收累计 64B，寄存 64B 快照 | 32B 包头及索引解析 | — |
| T2 | 接收累计 96B，最终快照入队，调度转PKG1 | 32B 偏移前三层；64B 包头及索引 | — |
| T3 | 接受 pkg0 最终请求；pkg1入队，调度转CTX | 32B 偏移后三层及定位；64B 前三层；96B 包头及索引 | — |
| T4 | 接受 pkg1 请求，可同时提交下一unit的context | 32B 不足，不输出；64B 后三层及定位；96B 前三层 | pkg1 包头及索引解析 |
| T5 | — | 64B 成功，寄存 pkg0 结果；96B 后三层及定位 | pkg1 偏移前三层 |
| T6 | — | 96B 重复成功，不输出，并清除去重位 | pkg0 距离1累加；pkg1 偏移后三层及定位 |
| T7 | — | — | pkg0 距离2累加；pkg1 提取并寄存解析结果 |
| T8 | — | — | pkg0 距离4累加；pkg1 距离1累加 |
| T9 | — | — | pkg0 距离8累加；pkg1 距离2累加 |
| T10 | — | — | pkg0 加锚点、颜色恢复和像素重排后寄存；pkg1 距离4累加 |
| T11 | — | — | pkg0 写输出缓存；pkg1 距离8累加 |
| T12 | — | — | pkg1 加锚点、颜色恢复和像素重排后寄存 |
| T13 | — | — | pkg1 写输出缓存，同时输出第1拍 |
| T14～T16 | — | — | 输出第2～4拍，T16 释放 slot |

若 pkg0 超过 64B，则在 T6 由 96B 快照交付；pkg1 调度及 T13 首拍不变。
若首份快照就足够，则 pkg0 在 T4 提前交付。

输入 slot 可在第四拍输出握手的同一沿接收新 unit 首拍，新分配优先于占用位清除。
旧 unit 的最终输出使用独立输出缓存，不再依赖该输入 slot。
这避免 slot 满时等待下一拍回收导致的周期性空拍。

## 周期与验证范围

| 工作负载 | 三个寄存点全开：首拍/末拍 | 全关：首拍/末拍 |
| --- | --- | --- |
| 原始 CBMD0 | T5 / T8 | T5 / T8 |
| Clear | T4 / T7 | T4 / T7 |
| 单扇区 DIC | T11 / T14 | T8 / T11 |
| 96B、pkg0=64B/pkg1=20B | T13 / T16 | T9 / T12 |
| 96B、pkg0>64B 或最终坏头 | T13 / T16 | T10 / T13 |

全关可在 pkg0 提前成功时立即切包；全开会继续发送最终快照，所以整机延迟差
不一定恰好等于新增寄存点数量。单份可完成快照从请求握手到输出缓存接收为
`6 + 开启的寄存点数` 个周期，整机延迟还包含输入和调度。

4 slot 的边界、反向边界、大包、短包和混合 DIC 连续测试首拍后空拍均为 0。
Clear 开头随后接 DIC 的启动切换，全开仍有 6 拍空拍，全关为 3 拍。
当前没有统一输出预填充，不能据此保证任意模式切换均连续。

```bash
bash tests/run_uddc.sh
UDDC_PARSE_OFFSET_REG=0 UDDC_PARSE_INDEX_REG=0 UDDC_PARSE_LAYOUT_REG=0 \
  bash tests/run_uddc.sh
bash tests/run_uddc_parser.sh
```

解析器八种寄存组合分别比较 3673 份快照，参考为 `66e10f3` 的独立解析器。
检查重复成功抑制、最终快照清理、tag 重用、两种包方向、最终错误及随机反压。
完整核心检查 2574 个 unit，并覆盖中途复位、输出稳定性和顺序。
这些周期验证不替代真实 TSMC7 工艺角下的综合、STA 和布局布线。

## RTL 数据表示与规则

全 RTL 禁止使用 packed/unpacked/匿名结构体，规则写入根目录
[AGENTS.md](../AGENTS.md)，由 `tests/check_rtl_style.py` 检查。
包头、索引、偏移和布局均使用独立命名的信号/数组；弹性寄存器接口仅用显式位宽
拼接传递这些字段。函数的多字段返回顺序由赋值拼接及相邻注释标明。
UDC候选及UDDC差分各级也使用独立命名字段连接 `de_rs_reg`；公共模块内部
用通用载荷总线保存两项数据，不使用结构体。

公共打拍模块保持全开/全关的最小延迟，容量由单项改为两项，反压恢复时序随之改变；
周期和功能由回归检查。
前三层与后三层的划分是 RTL 结构调整，尚无真实 TSMC7 工艺库下的时序签核结果。
