# UDC 32B 分拍编码

当前 `udc_enc_core` 使用 `udc_enc_stream` 处理每拍 32B 数据。
原来的 `udc_dic_enc` 及其五个子模块保留为独立的 64B 接口实现，但不再处于编码核心的数据通路中。

## 逐拍运算

`input_beat[0]` 选择包内前/后半拍，`input_beat[1]` 选择 pkg0/pkg1。
`original_partial` 和 `color_partial` 分别保存原始与颜色变换候选的原始通道平面、
差分、锚点、pair index 和每通道 global index。两种候选并行计算。

第一半拍只计算原始位位置落在低 256bit 的样本。第二半拍只计算高 256bit 样本，
并使用已保存的第一半拍平面完成跨拍预测。颜色变换使用同一像素的完整通道值；
格式 14 不做颜色变换，按实际 `(3*k+c)*32` 位位置区分两半，不能按各通道样本数简单对半。

每个新差分更新自己的 pair 最大索引和通道 global 最大索引。跨边界 pair 的第一个索引
在第一拍保存，第二拍用另一个差分的索引继续取最大值，不丢弃或重复计数。
第二半拍结束时，根据最终 pair 索引计算 pair 编码代价，与 global 编码代价比较；
相等时选 global。两个颜色候选按完整逻辑长度比较，相等时选原始候选。
这些规则与重构前的编码器相同。

## 缓存与握手

输入仍通过 `udc_enc_split` 保存 128B 原始数据，供压缩失败时回退。
其注册的 32B 请求同时交给 Clear 比较器和流式编码器，两者都能接收时才完成分发，
避免任何一支重复消费一拍。格式和尺寸限制从该 unit 的 slot 元数据读取。

流式编码器包含两项候选 FIFO，接收完整包的最终差分、策略、索引及长度，再交给
`udc_enc_package` 组装。该缓冲允许 DIC 在完整上下文交付前完成 pkg0；
不会因为包结果等待上下文、上下文等待最后一拍输入而形成相互等待。
FIFO 满时仍可接收只更新局部状态的前半拍；需要提交整包候选的后半拍通过 ready 反压。
包内边界状态仅在实际握手时更新。

Clear 命中且 limit 非零时，输出模块必须等两个 DIC 结果都接收完后才输出 Clear。
之后正常 retire，因此没有旧 DIC 结果落到复用 slot 的情况。
limit=0 时不产生 DIC 结果，输入收齐和 Clear 判断完成后直接选择 Clear 或原始数据。

`udc_enc_split` 原有的 64B `pkg_*` 调度接口目前保留以兼容独立模块使用；
核心对该接口置 ready=1，但压缩数据实际来自新的 32B 分发路径。
完整原始数据上下文仍在 Clear 判断完成后提交，这不会阻止逐拍 DIC 计算。

## 当前核心的无阻塞 pipeline

第一拍外部输入握手为 T0。表中结果在对应时钟沿寄存；两种颜色候选同拍并行。

| 时钟沿 | 32B 输入与 Clear | DIC 与输出 |
| --- | --- | --- |
| T0 | 接收并缓存第 1 拍，寄存分发请求 | — |
| T1 | 接收第 2 拍；比较第 1 拍 Clear | pkg0 前半拍差分及局部索引寄存 |
| T2 | 接收第 3 拍；比较第 2 拍 Clear | pkg0 后半拍计算、统计合并、策略和候选选择；进入候选 FIFO |
| T3 | 接收第 4 拍；比较第 3 拍 Clear | 组装 pkg0；计算 pkg1 前半拍 |
| T4 | 最后一拍 Clear 比较并产生结果 | pkg1 后半拍计算、合并和选择，进入 FIFO；pkg0 结果等待上下文 |
| T5 | split 接收 Clear 结果 | 两个包已完成差分与索引分析 |
| T6 | 向输出模块交付完整上下文 | — |
| T7 | — | 输出缓存接收 pkg0；组包寄存器同拍接收 pkg1 |
| T8 | — | 输出缓存接收 pkg1；DIC、Clear、原始回退所需信息齐全 |
| T9 | — | 首拍输出握手；最终模式决定还需输出几拍 |

四 slot 定向仿真确认：普通格式、双颜色候选格式及启用 DIC 的 Clear 均在 T9 首拍输出。
limit=0 的原始旁路或 Clear 保持 T7。输出最后一拍握手后才释放 slot。
本实现未加入输出最终包的同拍转发，也未将完整上下文交付提前，不能称为之前讨论的 T7 DIC 方案。

这是功能与周期优化，不是 TSMC7 1.5GHz 签核结论。第二半拍的差分、索引更新、
全包策略代价和颜色候选比较目前位于一个组合阶段；实际综合可能要求在合并/选择之间增加寄存级。

## 验证入口

```bash
python3 tests/check_rtl_style.py
bash tests/run_udc_stream.sh
```

新旧整机比对固定引用仓库提交 `b732757` 的编码器作为基线，分别使用不同的输入空拍和输出反压，
按输出顺序逐拍比较数据、CBMD、SOP、LAST 和 has_data，同时检查停顿稳定性。
测试含 512 个 unit，覆盖格式 0～15、不同压缩尺寸限制、Clear、可压缩与随机数据、slot 复用。
另有 18 组连续输入检查，每组 128 unit，检查模式选择、首拍周期和输入吞吐。
基线比对验证兼容性，不替代独立算法规范验证或 STA。

最终版本验证结果：512 个随机/混合 unit 与旧 RTL 逐拍一致，共比较 1385 拍输出；
18 组连续输入测试各 128 unit，共 2304 unit，均无输入停顿，每组最后一拍输入在 T511 接收。
这些连续测试采用全零 DIC 输入和固定 Clear 模板；随机数据及反压由前述混合测试覆盖。
RTL 风格与语法/展开检查覆盖整个当前 RTL；文件和 always 块数量以检查脚本输出为准。

## 文档与注释约定

UDC 与 UDDC 使用同一复位约定：复位期间不统计握手，组合逻辑不直接屏蔽
ready/valid，时序逻辑负责清除控制和有效位。RTL 文件头说明、nettype 指令及
translate_off/on 仿真块已移除；协议约束由本文、接口文档和测试平台说明。
本路径的 T9/T7 与 UDDC 的可选解析级无关；解码周期见
[UDDC 解析流水](UDDC_PARSER_PIPELINE.md)。
